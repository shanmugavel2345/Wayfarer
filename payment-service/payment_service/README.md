# Payment Service

Independent Java 17 / Spring Boot 3.5.7 learning microservice for bus booking payments.
All created payments remain PENDING. No money is transferred and no payment gateway,
Booking Service integration, or payment credential storage is implemented.
Booking IDs are external references, not foreign keys to another service's database.

## Run and test

From this directory, with Java 17 or later installed:

```powershell
.\mvnw.cmd clean verify
.\mvnw.cmd spring-boot:run
```

The API runs on port 8083. Swagger UI: http://localhost:8083/swagger-ui.html
OpenAPI JSON: http://localhost:8083/v3/api-docs
H2 console: http://localhost:8083/h2-console

The local database URL is `jdbc:h2:file:./data/paymentdb;MODE=PostgreSQL;DB_CLOSE_ON_EXIT=FALSE`.
Its location is relative to the process working directory. Local username defaults to
`sa` and the password is empty. Override using `PAYMENT_DB_USERNAME` and
`PAYMENT_DB_PASSWORD`; do not commit production secrets.

## API

| Method | Path | Result |
| --- | --- | --- |
| POST | /api/payments | 201, simulated pending payment, Location header |
| GET | /api/payments | 200, payment array |
| GET | /api/payments/{id} | 200, payment or 404 |
| GET | /api/payments/booking/{bookingId} | 200, payment array (empty if none) |

Example POST body:

```json
{"bookingId":42,"amount":125.50,"paymentMethod":"UPI"}
```

Methods: UPI, CARD, NET_BANKING. Amount must be positive, with at most 17 integer
digits and two decimal places to match database precision. Unknown fields are rejected,
including transactionId, paymentStatus, paymentDate and any credential fields.
Transaction IDs are UUIDs generated by the service. Payment date records request creation
in the server's local time, not settlement time. Repeated POSTs create separate records;
idempotency and booking existence validation are not implemented.

Errors contain timestamp, status, error, message and path. Unexpected failures use a
generic message without stack traces or internal details.

## Tests and deployment boundaries

PaymentServiceTest uses JUnit 5 and Mockito only; it never connects to a database.
PaymentControllerTest uses an MVC slice with a mocked service. The existing context
test uses an isolated in-memory H2 database instead of the local file database.

This configuration is for local learning, not an internet-facing payment system.
Before production, add authentication/authorization, external secret management,
database migrations instead of ddl-auto=update, operational monitoring and an actual
provider integration with verified callbacks and idempotency. Disable the H2 console,
SQL logging and public Swagger access. Never collect card numbers, CVV, UPI PINs,
passwords or banking credentials in this service.
